- 状态：已确认核心范围，部分技术与数据细节待验证
- 版本：Demo v1
- 日期：2026-11-08
- 关联文档：[技术方案与选型](TECHNICAL-DESIGN.md)、[开发计划与 Agent 协作规则](DEVELOPMENT-PLAN.md)

## 1. 产品概述

Quant Workbench 是面向个人 A 股研究者的量化分析与回测工作台。产品形态参考 Orca 的桌面工作区、任务流、多个工作区和产物呈现方式；不复制 Orca 的 coding-agent 编排能力。业务核心是数据、复盘、个股/板块研究、筛选、回测，以及可审计的 Agent 工具调用。

核心闭环：

> 准备数据 → 盘后复盘 → 研究股票/板块 → 筛选候选 → 回测假设 → 保存可复现结果 → Agent 辅助查询和执行研究任务

本文描述用户需要什么、行为应如何表现、怎样验收。具体代码结构与技术选择见技术方案；任务拆分与 agent 分工见开发计划。

### 1.1 实现原则：先找现成的，再改造

功能实现优先级固定为：**先找 GitHub 已有实现 → 能用就用 → 不合适就改造 → 都没有才自研**。自研不是默认选项。

- 调研时优先判断“能否直接依赖或薄适配”，不要一上来就重写。
- 需要照搬功能形态时（如复盘页、任务中心、回测器），允许改造复用，但必须按技术方案的三层复用规则执行，并先通过许可证检查。
- 改造的目标是可读性、代码结构、计算复杂度、可扩展性和测试覆盖，不是把别人的代码原样搬进来。
- 每个复用/改造项记录来源仓库、commit、许可证和改动范围；无法追溯来源的代码不得合入。
- 没有任何合适实现时才自研，自研同样遵守上述质量要求。

复用与自研的判断记录在 `research/REUSE-REGISTER.md`。

## 2. 用户与目标

### 2.1 首要用户

项目创建者本人，主要关注 A 股盘后研究、短线市场结构、事件统计和策略验证。v1 以单用户本地/私有环境为目标，不做 SaaS 多租户。

### 2.2 v1 产品目标

1. 在一个桌面工作台里完成从复盘到回测的核心研究流程。
2. 让结果能够追溯到数据日期、参数、指标口径和运行记录。
3. Agent 通过受控工具读取数据和提交研究任务，不能用生成文字替代计算结果。
4. 采用 Orca 式工作区和任务呈现体验，但优先保证量化工作流有效。
5. Demo 可由真实数据驱动；数据缺失时明确展示状态，不用假数据伪装成功。

### 2.3 已确认的 v1 决策

- 市场范围：沪深主板、创业板、科创板；包含新股和 ST；排除北交所。
- 默认基准：沪深 300；回测设计上保留切换基准的能力。
- 数据策略：优先寻找并验证 GitHub 上已有的数据包、数据湖或数据适配项目，再决定直接使用、适配、改造或补充接口。GitHub 项目未经字段、历史覆盖、质量和许可证验证前，不视为可用生产数据。
- Agent 入口：v1 同时提供工作台内置 Agent 面板和外部 MCP 接入；两者调用同一套受控业务服务。

以上是产品方向决策，不替代后续的数据验证、许可证审查和接口冻结。

### 2.4 v1 非目标

- 实盘交易、券商下单和自动荐股；
- 盘中实时行情、分钟线、Tick 和高频交易；
- 多市场；
- 多用户、组织权限、计费和公开云服务；
- 深度学习模型训练、自动因子进化；
- 原生移动端；
- 大规模分布式计算和复杂工作流编排。

## 3. 用户工作流

### 3.1 盘后复盘

打开最近完成的交易日 → 检查数据状态 → 浏览市场宽度、涨停/连板和板块表现 → 进入感兴趣的股票或板块 → 加入观察池或继续筛选。

### 3.2 个股/板块研究

从表格或图表选择对象 → 右侧上下文栏快速预览 → 在主工作区打开详情 → 查看行情、归属、历史事件、资金和统计数据 → 保存到观察池或创建研究任务。

### 3.3 筛选与回测

构建或载入筛选条件 → 查看结果和样本数 → 选择候选股票池、策略和区间 → 提交回测 → 在任务中心看进度 → 打开结果、检查成交明细和假设 → 保存运行记录。

### 3.4 Agent 研究

在 Agent 面板提出问题 → Agent 选择一个或多个只读/计算工具 → UI 显示每次工具调用及参数 → 结果返回结构化数据和依据 → 用户检查后决定是否继续提交任务。

## 4. 范围与优先级

### P0：Demo 闭环，缺一不可

- 工作台主布局、导航、多标签基本操作和当前对象上下文；
- 数据状态与最近交易日展示；
- 盘后复盘核心视图；
- 个股终端基础信息、日 K、关键统计和观察池操作；
- 基础筛选，结果可保存/复跑；
- 一个日频策略回测流程；
- 统一任务列表、进度、日志、错误和产物；
- MCP 基础查询工具，以及至少一个 Agent 驱动的研究任务；
- 关键指标口径、交易假设和结果版本可追溯。

### P1：有时间再加入，不能阻塞 P0

- 板块详情和板块历史共振；
- 表达式筛选（P0 可先做表单筛选）；
- 多回测参数对比；
- 命令面板；
- 工作区恢复和左右分屏；
- Markdown 报告归档和完成通知。

### P2：明确不属于 Demo v1

- 事件研究平台、完整因子研究平台；
- 模拟盘、实盘、券商接口；
- 分钟线和盘中监控；
- 多用户和移动端。

优先级用于范围控制。若工期缩减，先移除 P1，不以降低数据正确性或回测可信度换取页面数量。

## 5. 功能需求

### 5.1 工作台与工作区（P0）

主界面包含：

- 顶栏：产品/当前日期、远端连接、数据状态、命令入口；
- 左栏：功能导航、观察池、最近工作区；
- 主区：复盘、个股、筛选、回测和 Agent 工作视图，可开多个标签；
- 右栏：当前股票、板块、任务或运行结果的上下文；
- 底栏：运行任务摘要和日志入口。

工作区至少保存打开的页面/标签与当前选中对象。v1 不要求复杂协同或任意插件系统。客户端与 AutoDL 的连接状态必须显著可见；连接失败时不能伪装为实时数据。

### 5.2 市场复盘（P0）

指定交易日复盘至少包括：

- 主要指数表现；
- 上涨、下跌、平盘数量；
- 涨停、跌停、炸板和封板率（有可靠源时）；
- 连板梯队和最高连板；
- 行业/概念板块表现及可用的资金流；
- 涨停题材/原因及其股票列表；
- 数据日期、更新时间、数据完整性提示。

用户可切换日期、点击股票进入上下文/个股页、点击板块查看成分股、将股票加入观察池。

涨停原因的文本归类属于辅助信息，必须可回到原始来源或标注为模型/规则推断，不得与交易所事实混为一谈。

### 5.3 个股终端（P0）

至少展示：股票代码、名称、上市/交易状态、行业/概念、日 K、成交量、历史涨停/连板记录、可用资金流和龙虎榜、已实现的统计指标。

点击列表单击可在右栏预览，双击或明确操作可打开完整页面。所有统计值须展示窗口和样本数；样本不足时显示提示，不只显示百分比。

### 5.4 观察池（P0）

支持新增/移除股票、查看列表、持久化保存、从列表打开个股页。v1 可只有一个默认观察池；分组、备注、共享和提醒属于 P1/P2。

### 5.5 筛选器（P0）

P0 提供字段选择、比较条件、日期/窗口和 AND 组合的表单筛选。结果显示股票、关键字段、数据日期和结果数量；可排序、分页、加入观察池、保存条件并重新运行。

表达式模式不列为 P0。未来如实现，只允许白名单字段和运算符，禁止执行任意 Python/SQL。

### 5.6 回测（P0）

支持日频、单策略的基础回测：指定区间、股票池、初始资金、持仓限制、费率/滑点参数，输出净值、回撤、基准对照、分年统计和交易明细。

信号和成交必须分离。默认采用 T 日收盘后生成信号、最早 T+1 可交易时点成交；具体成交价和不可成交规则必须在回测报告中明确。相同数据快照、策略版本、参数和随机种子应复现一致结果，浮点比较容差由技术方案定义。

报告至少显示：累计收益、年化收益（样本长度足够时）、最大回撤、交易数、胜率、费用、基准和超额收益、样本区间、成交假设。不得只突出收益而隐藏风险指标。

### 5.7 任务中心（P0）

数据更新、批量筛选、复盘计算、回测和 Agent 发起的长任务统一进入任务列表。状态至少包括排队、运行、成功、失败、取消。每个任务可查看参数摘要、进度、日志、错误和产物；客户端重连后可查询仍在远端运行的任务。

取消只对支持安全中止的任务开放；取消失败要明确报告，不能标成已取消。

### 5.8 Agent 与 MCP（P0）

Agent 通过 MCP/平台 API 使用核心能力，不直接访问底层文件或数据库。首批能力：读取市场复盘、读取个股数据、筛选股票、读取涨停梯队、提交回测、查询任务和数据状态。

工具返回必须包含结构化结果、参数、数据日期、口径/版本、完整性提示和错误信息。UI 可查看工具名、参数、耗时、结果摘要和任务引用。

查询无需确认；提交计算任务须在 UI 中留有记录；删除数据、改全局配置等破坏性操作需要用户确认。v1 不包含交易工具。

### 5.9 数据更新与质量（P0）

用户可查看最近更新状态并手动触发更新/补数任务。自动定时更新时间、失败重试次数和历史补数范围在技术设计阶段确定。更新失败需保留错误和上次成功数据日期。

至少检查交易日完整性、股票覆盖数量异常、价格/成交数据异常、复权因子异常、股票状态冲突和关键源失败。质量失败必须阻止或明确警告相关研究使用不完整数据。

## 6. 指标口径与统计要求

所有指标在实现前必须进入指标字典，至少记录：标识、名称、公式/事件定义、输入字段、窗口、基准、样本过滤、输出、样本数、版本和测试用例。

“低开高走”等用户指标不得只记录名称。作为首个指标定义的讨论基线（待用户确认）：低开为开盘价较前收盘低至少 0.2%；收阳为收盘价高于开盘价；低开高走率为满足低开条件的样本中收阳比例；同时输出分母样本数。是否另报收红率（收盘高于前收盘）应单独列项。

所有胜率/比例类输出同时显示分子、分母或样本量。样本量阈值由指标字典逐项决定；低于阈值标记“样本不足”，不据此宣称稳定规律。市场强弱划分、行业中性化和超额基准也必须显式记录，不能默认为普适定义。

## 7. A 股数据与回测规则

下列规则属于正确性要求。具体规则参数须在技术设计和测试夹具中固定，不能由界面各自计算。

- 保存原始行情和复权因子；展示价格、收益计算和成交模拟分别注明采用的价格口径。
- 涨跌停价按当日适用规则和价格最小单位计算，并使用交易所/数据源可验证结果做样例测试。
- 规则需区分主板、风险警示股票、创业板、科创板和上市初期特殊交易日；v1 纳入新股与 ST，明确排除北交所。涨跌幅规则按证券在历史交易日的板块、风险警示状态和上市阶段确定，不能用当前状态回填历史状态。
- 停牌期间不得生成虚假成交；持仓估值规则在回测报告中声明。
- 分红、送转和除权除息需通过复权或现金/股份调整保持收益口径一致。
- 尽量保留退市股票和历史股票状态，避免幸存者偏差；若数据覆盖做不到，报告明确覆盖范围与偏差风险。
- 日历和信号执行顺序使用交易日历，不以自然日推算 T+1。
- 费用参数可配置，默认值和费率生效日期需可追溯。

首批市场范围已确认：沪深主板、创业板、科创板；包括新股和 ST，排除北交所。新股上市初期交易规则、ST 风险警示比例及其生效时间必须按历史日期处理。历史年限、基准指数和价格成交模型仍待评审确认。建议基准可配置，默认值在指标字典冻结时决定；信号 T 日收盘确认、T+1 开盘尝试成交作为建议默认。

## 8. 非功能验收

- 数据已加载且远端服务健康时，常用复盘查询目标 P95 小于 3 秒；验收记录网络条件、数据规模和缓存状态。
- 页面查询不应被长回测阻塞；耗时操作进入任务系统。
- 远端不可达时显示断连和最后成功数据日期；不显示未经标记的陈旧结果。
- 大型表格使用分页或虚拟滚动。
- 凭证不得写入 Git；远端 API/MCP 不允许匿名公网访问。
- 核心指标有口径测试；回测有固定数据黄金样本；API/MCP 有契约测试；数据管道有异常样本测试。

## 9. 原型验收

HTML 原型由专门的 UI 原型 agent 根据 PRD 制作，范围列入开发进度表。原型包含复盘、个股、筛选、回测、任务和 Agent 的关键状态，以及右栏上下文和底部任务栏。

交互至少贯通：复盘选股 → 个股预览/详情 → 加入观察池或筛选 → 提交回测 → 查看任务与结果。静态示例数据需显著标记，不得呈现为真实行情。原型评审通过后再冻结主布局，不能把原型中的任意细节自动视为需求变更。

## 10. 验收场景

1. 用户能看到最近交易日、数据更新时间和远端连接状态。
2. 用户可以从复盘打开个股，并将其加入持久化观察池。
3. 用户可以建立、保存并重跑一条筛选条件，看到结果数和数据日期。
4. 用户提交日频回测后可查看任务状态、参数、结果、基准、回撤和交易明细。
5. 断开客户端再连接后，仍能查询远端任务与已完成结果。
6. Agent 能通过工具查询复盘，并能提交回测、查询任务；工具参数和结果可审计。
7. 数据质量异常时，UI 和 Agent 都明确返回异常状态。
8. 固定输入的回测黄金样本满足定义的误差容限并可重复运行。

## 11. 待确认决策

PRD 评审必须确认：

1. 已确认市场范围：包含沪深主板、创业板、科创板、新股和 ST，排除北交所；实现前确认历史规则数据可得性；
2. 已确认默认基准为沪深 300；历史年限和基准切换范围待技术验证；
3. 低开高走、市场强弱、板块共振等指标字典；
4. 用户是否需要表达式筛选进入 P0；
5. 原型优先覆盖桌面端的最小分辨率；
6. 数据源授权、AutoDL API 访问和鉴权方式；
7. 已确认 v1 同时提供内置 Agent 面板和外部 MCP；具体模型和 MCP 传输方式待技术验证。

产品范围冻结后，新增需求按开发计划中的变更流程处理。
